# Contributing to Ramen

Use it, fork it, change it — with attribution. The full guidelines (what we ask of forks and products built on
Ramen, how a change gets in, the test and contract rules, the related repositories) are in [the contributing guide](https://bkraad47.github.io/ramen/contributing/).

The short version:
- Open an issue before anything larger than a fix.
- Tests first; every component has a suite and CI runs them on Linux and Windows plus a compose end-to-end stack.
- A change to a contracted surface updates `CHANGELOG.md` in the same change.
- Keep the project's name and copyright notice with the code (BSD-3-Clause). Renaming Ramen and presenting it as
  a new commercial product of your own, with the origin removed, is not acceptable.
- Security issues: mail the maintainer, not a public issue.
