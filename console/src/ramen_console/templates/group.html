Service-account permissions

Approved permissions per zone are bound to the zone's service account (least privilege, F6.5). A group admin requests a permission for a zone, a super admin approves it, and the console binds the matching cloud roles (GCP IAM / AWS IAM) to that zone's identity — revoking takes them away again. Scope names the resources the permission is for: leave it empty (or *) and bucket.* covers the group's own area of the groups bucket and secrets.* the group's secrets; name buckets or secrets (bucket-a, bucket-b) and the binding is on those alone. Permissions whose cloud roles are project-wide (logs, metrics, queues, …) record the scope but cannot enforce it. On GCP the console's identity manages IAM only on the groups bucket: to scope to another bucket, grant it roles/storage.admin on that bucket first (the approval tells you if it is missing).

How MCP users sign in

People with an MCP User (or any) role in this group reach its workers with their own identity — expand for the HTTP and bridge setups

Sign-in goes through this console{% if providers %} — with password, magic link or the configured provider{{ 's' if providers|length != 1 }} {{ providers|join(', ') }} (Microsoft Entra ID / Google Workspace are OIDC providers; their roles map on the Config page){% endif %}. The client is an OAuth client a super admin registered on the Config page; the person approves it once per zone and the token is scoped to mcp:{{ group.id }}:<zone>.

HTTP (Claude Code, Claude Desktop, Cursor):

claude mcp add-json ramen-{{ group.id }} '{"type":"http","url":"{{ public_url }}/mcp",
  "headers":{"ramen-group":"{{ group.id }}","ramen-zone":"<zone>"},
  "oauth":{"clientId":"<client id>","scopes":"mcp:{{ group.id }}:<zone>"}}'

Bridge (stdio clients, ramen-mcp-bridge 0.2.0+):

ramen-mcp-bridge --target <host>:443 --tls --oauth {{ public_url }} --client-id <client id> --group {{ group.id }} --zone <zone>

The first run opens the browser on this console's sign-in page (password, magic link or the configured provider); the refresh token is kept in ~/.config/ramen-mcp-bridge/. A group agent key (--key rmk_…) still works for automation.

Service-account restrictions

What this group's admins may request for its zones, on top of the super-admin rules on the Config page. A JSON list of {"effect": "allow|deny", "permission": "glob"}, checked when a request is made (never against permissions already granted): a deny rule matching the permission refuses it; when the list has allow rules, the permission must match one of them; with no rules anything the super-admin rules permit can be requested. Globs are shell-style — bucket.*, *.write, *. A rule that allows what a super-admin rule denies is rejected (409). Example: [{"effect": "allow", "permission": "bucket.*"}, {"effect": "deny", "permission": "bucket.write"}] lets admins request only bucket reads.
